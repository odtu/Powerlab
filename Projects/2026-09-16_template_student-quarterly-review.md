**How to write an acceptance criterion — from our own work**

| Vague | What it should be |
|---|---|
| Finish the prototype tests | v2.0 ran under load on the bench; no-load and locked-rotor measurements taken; torque constant measured at three operating points; raw data and plots committed |
| Improve the FEA model | Measured torque and temperature rise compared against the 3D model at the rated point; either within 10% or the reason for the difference written in the issue |
| Work on the journal paper | Paper submitted to IEEE TPEL, submission number recorded in the issue |
| Optimise the winding | Two PCB winding topologies built and measured at the same current density; torque, loss and temperature rise tabulated; one recommended with reasons |
| Do the PCB revision | Rev C Gerbers out, ordered, boards received and powered up |
| Look into the efficiency problem | Loss breakdown measured at the rated point, compared against the calculation, and the component responsible for the gap identified |
| Write thesis chapters | Chapters 2 and 3 reached me as PDFs; figures, references and conclusion all in place |

If a criterion names a number, a measurement, a file or a confirmation, it is a good one.
If it says "improve", "work on", "continue" or "look into", it is not.
